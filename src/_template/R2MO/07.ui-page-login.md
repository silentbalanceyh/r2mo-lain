使用 `r2-dev-login` 技能开发登录认证模块（`src/pages/login.rs`）。登录是系统的安全入口，根据 `requirement.page.md` 中的认证需求，选择合适的登录方式组合（不是所有系统都需要全部方式）。

**可用的认证方式** (8+ 种，按需启用):
- 标准账密登录 (`/auth/login`) - 最基础，几乎所有系统必需
- JWT 令牌登录 (`/auth/jwt-login`) - 增强版本，现代化应用推荐
- LDAP 企业目录登录 (`/auth/ldap-login`) - 仅企业/政府系统需要
- 短信验证码登录 (`/auth/sms-login`, `/auth/sms-send`) - 移动优先应用或 2FA 需要
- 邮箱验证码登录 (`/auth/email-login`, `/auth/email-send`) - 邮件优先应用需要
- 微信公众号登录 (`/auth/wechat-qrcode`, `/auth/wechat-status`, `/auth/wechat-callback`) - 仅中国区应用
- 企业微信登录 (`/auth/wecom-init`, `/auth/wecom-login`, `/auth/wecom-qrcode`) - 仅企业内部应用
- OAuth2/OIDC 标准协议 (`/oauth2/token`, `/oauth2/revoke`, `/userinfo`) - SaaS/平台级应用

**常见的登录方式组合**:
- **最小配置** (初创/小型应用): 标准账密 + 可选邮箱验证
- **标准配置** (中型应用): 标准账密 + JWT + 邮箱/短信验证
- **企业配置** (企业/政府): LDAP + 标准账密 + OAuth2
- **中国本地应用**: 标准账密 + 微信/企微 + 短信验证
- **SaaS/平台**: OAuth2/OIDC + 标准账密 + 多社交登录

**关键输入**:
- `requirement.page.md` (认证需求: 明确指定所需的登录方式列表)
- `.r2mo/api/metadata.yaml` 中 `/auth/**` 和 `/oauth2/**` 接口定义 (提供可用的 API 端点)
- `.r2mo/api/marker.md` (表单字段属性: 账号、密码、验证码类型)
- `.r2mo/design/spec.md` (设计规范: 登录页背景、表单样式)

**必须遵守**:
1. **按需启用** - 仅实现 requirement.page.md 中指定的登录方式，不过度设计
2. 验证码接口调用流程: send → countdown → login (有倒计时，失败可重试)
3. 短信/邮箱验证码: 获取 → 倒计时 (60秒) → 提交
4. 微信/企微登录: 获取二维码 → 轮询状态 → 登录回调
5. OAuth2/OIDC: 获取授权码 → 交换 Token → 获取用户信息
6. API 路径和字段严格来自 `/auth/**` 和 `/oauth2/**` 接口定义，不硬编码
7. Token 存储到 localStorage/sessionStorage，在 Authorization header 中携带
8. 表单字段属性严格遵循 marker.md (长度、格式、验证规则)
9. 错误处理: API 错误 → 用户友好的中文提示，区分认证失败/系统错误
10. UI 设计: 仅显示已启用的登录方式选项卡，隐藏未启用的方式

**输出**: src/pages/login.rs (根据需求定制的认证模块，只包含指定的登录方式)
